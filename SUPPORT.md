# Support Policy for EricksonLopez.Caching

Thank you for adopting **`EricksonLopez.Caching`**! We provide support through the following channels:

---

## 1. Official Documentation & Architecture

Before raising an issue, please check the architectural documentation:
- **[Sequential Reading Roadmap](docs/README.md)**: Architectural justification, multi-tier topology, and design principles.
- **[Architecture Decision Records (ADRs)](docs/adr/README.md)**: Rationale behind stampede protection, Result pattern, Native AOT invariants, and backplane boundaries.
- **[Framework Testing Roadmap](docs/testing-roadmap.md)**: Test coverage, Stryker mutation scores, and fitness function audit.

---

## 2. GitHub Issues & Discussions

- **Bug Reports**: If you experience unexpected exceptions, cache inconsistency, or Native AOT trimming warnings, please open a [GitHub Issue](https://github.com/ericksonlopezf/dotnet-caching/issues) with a minimal reproducible sample.
- **Feature Requests**: If your domain requires new caching capabilities or provider extensions, submit a feature request on GitHub Issues.
- **Questions & Discussions**: For design questions and integration best practices, use [GitHub Discussions](https://github.com/ericksonlopezf/dotnet-caching/discussions).

---
